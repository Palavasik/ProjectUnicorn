# CJM: путь пользователя в боте (актуальный интерфейс)

Документ описывает **текущие** шаги сценария в Telegram: что видит пользователь, **формат ввода и вывода**, краткая **логика** шага. Источник правды — код в `src/handlers/` (в первую очередь `commands.py`, `search.py`, `messages.py`).

Состояния диалога поиска (`ConversationHandler`): **`LOCATION`** → **`DISTANCE`** → завершение разговора; дальнейшие действия (выбор маршрута, отзыв) идут **вне** состояний, через `callback_query` и отдельные обработчики.

---

## 0. Главный экран (вне поиска)

| | |
|--|--|
| **Как попасть** | Команда `/start`, кнопка «🏠 Главная», callback «В начало» после поиска. |
| **Ввод** | Не требуется (или команда `/start`). |
| **Вывод** | Текст приветствия: обращение по `first_name`, кратко о боте, призыв начать поиск. |
| **Клавиатура (Reply)** | Ряд 1: `🏠 Главная` \| `🔍 Найти маршрут`; ряд 2: `❓ Помощь` \| `Отмена`. |
| **Логика** | Показ главного меню; при `/start` — upsert пользователя в БД (если настроено). |

**Текст приветствия (шаблон):**  
`Привет, {first_name}!` → описание Project Unicorn → «Нажмите кнопку ниже, чтобы начать поиск.»

---

## 1. Справка

| | |
|--|--|
| **Как попасть** | Команда `/help` или кнопка `❓ Помощь`. |
| **Ввод** | Команда или нажатие кнопки. |
| **Вывод** | Текст со списком кнопок и упоминанием команд `/start`, `/find`, `/help`, `/cancel`. |
| **Логика** | Статическая справка (без смены состояния поиска). |

---

## 2. Старт сценария поиска

| | |
|--|--|
| **Как попасть** | Команда `/find` или кнопка `🔍 Найти маршрут` (также срабатывает совпадение с текстом «Найти маршрут»). |
| **Ввод** | Текст команды или нажатие кнопки (точное совпадение с подписью кнопки). |
| **Вывод** | Сообщение с инструкцией по точке старта. |
| **Клавиатура** | Одноразовая: `Отправить геолокацию` (запрос геолокации), `Назад`. |
| **Состояние** | Переход в **`LOCATION`**. |
| **Логика** | Фиксируется время начала «сессии» для аналитики; запрос точки старта. |

**Текст запроса точки (суть):**  
Отправить геолокацию **или** ввести координаты **или** адрес; примеры формата координат и адреса; замечание про десктоп/web Telegram.

---

## 3. Шаг «Стартовая точка» (`LOCATION`)

Пользователь должен передать координаты или адрес одним из способов ниже.

### 3.1. Геолокация

| | |
|--|--|
| **Ввод** | Сообщение с вложением **Location** (кнопка «Отправить геолокацию»). |
| **Вывод** | `Точка старта принята.` + пустая строка + `Выберите дистанцию:` |
| **Клавиатура** | Inline: три варианта дистанции + `← Назад` + `В начало` (см. п. 4). |
| **Состояние** | **`DISTANCE`**. |
| **Логика** | Сохраняются `latitude` / `longitude`; метка для аналитики. |

### 3.2. Координаты текстом

| | |
|--|--|
| **Ввод** | Одна строка: **широта** и **долгота**, разделитель — запятая, `;` или пробел. Пример в UI: `55.7558, 37.6173`. Допустимы отрицательные значения в допустимых диапазонах. |
| **Вывод** | Как в п. 3.1 (принято → выбор дистанции). |
| **Состояние** | **`DISTANCE`**. |
| **Логика** | Парсинг regex; при успехе — сохранение lat/lon. |

### 3.3. Адрес текстом (не координаты)

| | |
|--|--|
| **Ввод** | Строка длиной **≥ 3** символов, не подходящая под формат координат (например: `Москва, Красная площадь 1`). |
| **Вывод (успех)** | `Точка старта: {display_name}` + пустая строка + `Выберите дистанцию:` + inline-клавиатура дистанции. |
| **Вывод (адрес не найден)** | Сообщение об ошибке + снова запрос точки с той же reply-клавиатурой (геолокация + «Назад»). |
| **Вывод (геокодер недоступен)** | Сообщение о недоступности сервиса + снова запрос точки. |
| **Состояние** | При успехе — **`DISTANCE`**; при ошибке — остаётся **`LOCATION`**. |
| **Логика** | Асинхронный вызов геокодера (Яндекс при ключе, иначе Nominatim). |

### 3.4. Слишком короткий текст

| | |
|--|--|
| **Ввод** | Текст короче 3 символов (и не координаты). |
| **Вывод** | Предупреждение о коротком запросе + повторная инструкция + reply-клавиатура запроса точки. |
| **Состояние** | **`LOCATION`**. |

### 3.5. Навигация на этом шаге

| | |
|--|--|
| **Ввод** | Текст `Назад` (reply-кнопка). |
| **Вывод** | Экран главного меню (как п. 0): приветствие + постоянная reply-клавиатура. |
| **Состояние** | Выход из сценария (`END`), данные поиска сбрасываются. |
| **Логика** | `_back_to_start_handler` → `start_handler`. |

## 4. Шаг «Дистанция» (`DISTANCE`)

Сообщение с выбором дистанции — **inline**-клавиатура под предыдущим сообщением («Точка старта принята…» / «Точка старта: …»).

| Кнопка (подпись) | `callback_data` | Значение для LLM (км) |
|------------------|-----------------|------------------------|
| Короткая (3–5 км) | `distance:short` | 4 |
| Ежедневная (10 км) | `distance:daily` | 10 |
| Длинная (18–20 км) | `distance:long` | 19 |
| ← Назад | `search_back:location` | — |
| В начало | `search_back:start` | — |

### 4.1. Выбор дистанции (одна из трёх)

| | |
|--|--|
| **Ввод** | Нажатие inline-кнопки `distance:*`. |
| **Вывод (успех LLM)** | Сообщение **редактируется** (то же сообщение, где были кнопки дистанции): HTML-текст со списком маршрутов (см. п. 5) + под каждым маршрутом кнопка «Построить маршрут N в Яндекс.Картах». |
| **Вывод (пустой список маршрутов)** | Текст о том, что маршруты не найдены + предложение сменить точку/дистанцию + «Найти маршрут». |
| **Вывод (ошибка LLM / сервиса)** | Текст ошибки (пользовательский) + «Найти маршрут»; или общее сообщение об ошибке поиска. |
| **Состояние** | Разговор **`END`**; маршруты кладутся в `user_data["search_routes"]` до выбора или истечения. |
| **Логика** | Вызов LLM с (lat, lon, distance_km); при успехе — опционально логи в `ANALYTICS_CHAT_ID`; затем `edit_message_text` с результатом. |

### 4.2. «← Назад» на шаге дистанции

| | |
|--|--|
| **Ввод** | `search_back:location`. |
| **Вывод** | **Новое** сообщение с текстом запроса точки старта (как в п. 2) + reply-клавиатура «Отправить геолокацию» / «Назад». |
| **Состояние** | Возврат в **`LOCATION`**. |
| **Логика** | Пользователь может заново ввести точку; координаты предыдущего шага остаются в `user_data` до замены. |

### 4.3. «В начало» на шаге дистанции

| | |
|--|--|
| **Ввод** | `search_back:start`. |
| **Вывод** | Новое сообщение: приветствие главного меню + reply-клавиатура главного экрана. |
| **Состояние** | **`END`**, состояние поиска очищено. |

---

## 5. Экран результатов LLM (после выбора дистанции)

Сообщение одно, **редактированное** (inline под ним).

| | |
|--|--|
| **Формат вывода (есть маршруты)** | Первая строка-вводная: «Вот варианты маршрутов…» Затем блоки **номер + название** (жирным) и **описание** (обычный текст), между блоками — пустая строка. |
| **Inline-кнопки** | Для каждого варианта: `Построить маршрут {N} в Яндекс.Картах` → `route_select:{N-1}`. |
| **Формат вывода (нет маршрутов)** | Текст о том, что маршруты не найдены; кнопок построения нет. |
| **Логика** | Данные из ответа LLM (`name`, `description`); координаты хранятся для ссылки на карты. |

---

## 6. Выбор маршрута и ссылка на Яндекс.Карты

| | |
|--|--|
| **Ввод** | Нажатие `Построить маршрут N в Яндекс.Картах` (`route_select:i`). |
| **Вывод** | То же сообщение **редактируется**: название маршрута (жирным), строка «Построить маршрут в Яндекс.Картах:», гиперссылка **«Открыть маршрут»** (URL с полилинией `rtext=…`). |
| **Новое сообщение** | Текст: `Как вам маршрут?` + inline: `Отлично`, `Норм`, `Не зашло`, `Пропустить` (`feedback:5`, `feedback:3`, `feedback:1`, `feedback:skip`). |
| **Логика** | Ссылка строится из массива координат маршрута; список `search_routes` очищается после выбора; сохраняются имя маршрута и дистанция для отзыва. |

**Ошибка:** если сессия истекла — текст «Сессия истекла…» без ссылки.

---

## 7. Обратная связь по маршруту

| | |
|--|--|
| **Ввод** | Одна из кнопок оценки или «Пропустить». |
| **Вывод** | Сообщение с вопросом **редактируется**: при пропуске — «Ок, удачных пробежек!»; при оценке — «Спасибо за отзыв!» (или «Спасибо!» при неверных данных). |
| **Логика** | При числовой оценке — запись в БД (`insert_feedback`), если есть user id и имя маршрута; очищается `search_distance`. |

---

## 8. Прерывание и побочные переходы

| Ситуация | Ввод | Результат |
|----------|------|-----------|
| Отмена поиска | `/cancel` или кнопка `Отмена` (fallback в сценарии поиска) | «Поиск отменён…» + сброс состояния поиска. |
| Главная во время поиска | Кнопка `🏠 Главная` | Как `/start`: приветствие + главная клавиатура, сброс данных поиска. |
| Произвольный текст вне сценария | Любое текстовое сообщение без совпадения с обработчиками | «Не понимаю…» (`fallback_handler`). |

---

## 9. Сводка потока (схема)

```text
/start, Главная
       → главное меню
🔍 Найти маршрут / /find
       → LOCATION: геолокация | координаты | адрес | Назад → главная
       → DISTANCE: дистанция | ← Назад → LOCATION | В начало → главная
       → результаты LLM (список + кнопки Яндекс.Карт)
       → экран ссылки + «Как вам маршрут?»
       → отзыв или пропуск
```
